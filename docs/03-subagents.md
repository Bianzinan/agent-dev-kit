# 03 · 子 Agent

子 Agent（subagent）运行在**独立的上下文窗口**中，完成任务后只把结论返回主会话。
它的核心价值是**上下文隔离**：把消耗大量 token 的探索过程挡在主会话之外。

## 定义格式

`agents/<name>.md`：

```markdown
---
name: code-reviewer
description: 审查已暂存或最近改动的代码，聚焦正确性、安全性与可维护性。在提交或发起 PR 前主动使用。
tools: Read, Grep, Glob, Bash
model: inherit
---

你是资深代码审查者。...
```

### frontmatter 字段

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | kebab-case，与文件名一致 |
| `description` | 是 | 何时该调用这个 agent；写"主动使用"可提升自动触发概率 |
| `tools` | 否 | 允许使用的工具白名单；省略则继承全部工具 |
| `model` | 否 | `inherit` / `sonnet` / `opus` / `haiku` |

正文是该 agent 的系统提示词，应写明工作流程、重点检查项、明确的禁止事项和输出格式。

## 何时该用子 Agent

✅ **适合：**

- 需要大量探索才能得出简短结论（搜索整个代码库定位某个行为）
- 独立且可并行的任务（同时审查多个模块）
- 输出冗长但结论简短（跑测试套件，只需要"通过/失败 + 失败原因"）

❌ **不适合：**

- 只需 2–5 次工具调用就能完成的事——直接做更快
- 需要频繁与主会话来回确认的任务
- 主会话已经掌握全部上下文的小改动

## 编写要点

1. **子 Agent 是无状态的**——每次调用都要在 prompt 里提供完整上下文，它看不到主会话历史。
2. **明确禁止事项**——例如 code-reviewer 明确写"不评论格式问题"、"不修改代码"，
   否则它会输出大量噪音。
3. **规定输出格式**——结构化的输出（分级、`文件:行号`）才便于主会话消费。
4. **收敛工具权限**——只读型 agent 就不要给 Edit / Write。

## 本仓库内置

| Agent | 用途 |
| --- | --- |
| `code-reviewer` | 审查改动，按 Blocking / Warning / Info 分级输出 |
| `test-runner` | 探测并运行项目测试，通过时只回一行摘要，失败时给完整诊断 |

## 与斜杠命令配合

`commands/` 下的斜杠命令可以显式调用子 Agent，把多步流程固化下来：

- `/review [范围]` —— 调用 `code-reviewer`
- `/ship [说明]` —— 依次执行校验 → `test-runner` → `code-reviewer` → 生成提交信息

命令正文中的 `$ARGUMENTS` 会被替换为用户输入的参数。
